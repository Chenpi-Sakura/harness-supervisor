## 1. 问题与根因

Qoder CLI 1.1.82 下所有 Worker 启动失败。真实二进制复现出两个独立变化：

1. **参数冲突**：`--permission-prompt-tool stdio` 不能与
   `--input-format stream-json` 同时使用。CLI 在认证和模型调用之前直接退出：

   ```text
   --permission-prompt-tool stdio cannot be combined with --input-format stream-json
   ```

2. **初始化顺序**：移除冲突参数后，1.1.82 在 stream-json 输入模式下收到第一条
   user 消息后才初始化并发出 `system init`；HS 原来先等 `system init` 再发
   prompt，双方互相等待直到启动超时。

同一组参数在 1.1.79 上没有冲突。进一步用真实 1.1.79 进程验证：不传
`--permission-prompt-tool stdio` 时仍会收到 `can_use_tool` 控制请求，因此该参数
本来就是冗余的，可以安全移除。

## 2. 实施

- 移除 Qoder 启动参数中的 `--permission-prompt-tool stdio`；继续在
  `RESERVED_ARGS` 中禁止 `extraArgs` 重新引入。
- 增加 `HarnessSpawnSpec.initialPrompt`，由 Supervisor 传入同一条已带 Worker
  协议块的初始提示。
- Qoder 会话启动时先等待 init 1 秒；若未到达则提前发送初始提示以触发懒初始化，
  并等待 init 完成后再返回。Supervisor 随后的 `prompt()` 对同一条提示去重，
  不重复发送；1.1.79 通常仍在 1 秒内完成 init，保持原顺序。
- 假 Qoder 增加与 1.1.82 一致的参数拒绝逻辑，以及
  `FAKE_QODER_INIT_AFTER_PROMPT` 懒初始化场景；集成测试断言启动 argv 不再包含
  冲突参数、初始提示只发送一次。
- 能力说明和 README 如实记录 1.1.82 的限制：stream-json 默认权限模式下
  AskUserQuestion 不再产生控制请求，1.1.82 建议使用 `bypass_permissions`
  （默认）或 `dont_ask`。

## 4. ACP 与 SDK 调研

官方资料确认：

- **ACP**：`qoder --acp` 是公开支持的 ACP Server，使用标准输入输出通信；支持
  权限配置、工具、MCP、上下文压缩和多模态。真实 1.1.82 已验证
  `initialize`、`session/new`、模式切换和 Write 工具的
  `session/request_permission`。后续补充探测确认：客户端声明
  `clientCapabilities.elicitation.form` 后，AskUserQuestion 会以
  `elicitation/create` 到达并可回答；未声明能力时不会发送。
- **Agent SDK**：官方 TypeScript/Python/Java SDK，通过本地 qodercli 的 SDK 模式
  通信；`canUseTool` 同时处理工具审批和 AskUserQuestion。SDK 要求显式认证方式
  （PAT、Service Account 或本地 CLI 登录），并会向 qodercli 传递临时认证载荷。

判断：

- ACP 更符合 HS 的轻量、运行时无关边界：不新增 SDK 依赖，不接管凭据，且 HS
  已有 ACP 客户端实现（MiniMax Code）。它适合作为下一阶段 Qoder 的
  **可选传输层**，用于恢复 1.1.82 的工具审批能力。
- SDK 的交互能力更完整（特别是 AskUserQuestion），但引入包依赖和认证载荷管理，
  会改变当前“只调用原生 CLI、凭据归原生工具”的边界；暂不作为默认路径。
- 本轮不重写适配器；先交付经过真实验证的 stream-json 兼容修复。ACP 接入需单独
  验收 prompt、审批、提问、取消、resume、用量与文件/终端能力后再决定是否设为默认。

## 6. 已知限制

- 1.1.82 stream-json 模式下，需要用户回答的 AskUserQuestion 不再由 CLI 暴露为
  `awaiting_input`；这是上游行为，HS 不会伪造请求。
- 1.1.82 的初始化依赖首条 user 消息，因此权限模式的降级校验只能在首条提示发送后
  完成；发现不匹配时仍会终止启动，但可能已有一次模型调用。
- ACP 的 AskUserQuestion 需要客户端声明 elicitation 能力；声明后已真实验证
  `elicitation/create` 可回答，但尚未接入 HS。完整可行性见
  `docs/acp-feasibility-261104.md`。
- 1.1.82 仍不会报告真实 Token（`result.usage` 全零按未知处理）。
