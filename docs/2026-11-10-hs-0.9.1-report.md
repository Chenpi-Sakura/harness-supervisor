## 2. 范围与数据分层

本版本只改 MCP 返回层，不重构 Worker 生命周期，不改变事件落盘格式、CLI/IPC 状态语义或原生 Harness 行为。

返回数据按三类处理：

| 类别 | 默认位置 | 说明 |
| --- | --- | --- |
| 生命周期与决策数据 | Production | 身份、状态、游标、session 可用性、bounded preview、pendingInput、完整 wait 结果 |
| 诊断与进程数据 | Development 或显式读取 | events/progress、timeline、PID、stderrTail、storage、原始 usage 记录 |
| 大交付物与历史 | 按需读取 | 完整最终结果只随 `worker_wait` 返回；不在 `worker_status` 或列表重复 |

## 4. 关键实现

- **事件白名单**：`src/event-policy.ts` 集中维护 Production 允许的 lifecycle 类型。`run.progress`（thinking、assistant delta、tool start/end、usage 等）永不进入 Production。
- **状态快照**：`worker_status` 投影后删除 cwd、完整 result/error、recentEvents、lastProgress、timeline、inputState，再对完整响应重新测量并收缩 2 KiB 预算；`includeInput=true` 是显式例外。
- **等待语义**：`worker_wait` 完成时返回 Supervisor 存储的完整最终结果（`result.truncated` 只反映存储层 `maxResultBytes`），不在 MCP 层截断；超时不返回历史；`until=event` 未指定 `types` 时只等待 lifecycle 白名单，空 `types` 同样归一化，progress 不会结束等待；事件批次最多 10 条/4 KiB。
- **事件读取**：Production 无 `sinceSeq` 时为尾部快照（最多 10 条 lifecycle，4 KiB），严格增量默认 100、最大 200；`eventsOmitted`/`progressOmitted` 说明省略。
- **列表分页**：排序 `(createdAt DESC, id ASC)`；cursor 是最后一条已返回记录的 `(createdAt,id)`，Base64URL 不透明；IPC 新增可选 `after`，MCP 请求 `limit+1` 推断 `hasMore`。1,200 个 Worker 全量翻页、并发新增/归档/遗忘、畸形与非规范 cursor 均有测试。
- **旧 Daemon 兼容**：Production 仍需 daemon ≥0.4.0；`worker_list` cursor 需要 0.9.1，旧 Daemon 第一页可用、cursor 页返回带升级指引的 `UNSUPPORTED`；旧 Daemon 缺少 `session` 投影时，Development 状态与 `worker_resume.sessionRestored` 均不崩溃、不补造值。
- **通知与度量**：Production 不返回 delivery 历史、routing target、原始 usage 记录或 token 明细；Development 返回显式白名单。
- **错误投影**：Production 保留 code、可操作消息和必要 ID（requestId/workerId/status/reason/nextActions），不返回堆栈、路径或完整 details。

## 5. 真实 Harness 验收

在最终 0.9.1 代码上使用真实 Qoder CLI 1.1.82（ACP，正常 `~/.qoder` 登录）与 MiniMax Code 0.7.0（ACP）各跑一次 Production MCP 最小任务：

```text
worker_spawn -> worker_wait -> worker_status -> worker_events
```

| Runtime | spawn | wait | status | events | Development status |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qoder 1.1.82 | 536 B | 355 B | 406 B | 544 B | 7,211 B |
| MiniMax Code 0.7.0 | 536 B | 355 B | 406 B | 544 B | 7,367 B |

两者均满足：

- `worker_wait` 返回完整 19 字符结果一次，`truncated=false`，无 `events`。
- `worker_status` 只有 `worker`，有 `resultPreview`/`resultAvailable`，无 `recentEvents`/`timeline`/`lastProgress`/`inputState`/`cwd`/`pid`/`sessionFile`。
- `worker_events` 仅 6 条 lifecycle 事件，无 `run.progress`、无事件 `data`。
- Production 响应无 thinking/text-delta 内容、无被禁诊断字段。

本次复验中 Qoder 产生 37 条 `run.progress`（含 `thinking`），MiniMax Code 产生 24 条（含 `thinking`）；Production 全部过滤（`progressOmitted=37/24`），Development 才可见原始事件。progress 条数随模型流式输出变化，不影响过滤结论。

证据：`evidence/mcp-runtime-acceptance-261110/`（README、result.json），脚本：`scripts/e2e-mcp-runtimes.mjs`。

**限制**：每次仅一次文本任务；不含 Desktop 模型回合、Persistent 多轮 MCP 连续性、steer 或权限审批；Pi 与 DSH 本轮未做真实 MCP 验收。

## 6. 测试与构建

- 构建：`npm run build` 通过（TypeScript 无错误）。
- 全量：`npm test`，最终精确树 405 个测试，403 通过，0 失败，2 个真实 Pi 付费测试按设计跳过。
- 定向：`mcp-presentation`、`mcp-list-pagination`、`mcp-modes` 共 35/35 通过；包含 1,200 Worker 全量分页、并发变更、旧 Daemon cursor、旧 Daemon resume、until=event progress 过滤和 wait 事件预算；最终全量另覆盖旧 Daemon 0.6.0 的 `includeArchived` 兼容用例。
- 响应体积：Production `spawn + wait` 主链为 533 B + 20,375 B（20k 字符最终报告）；`worker_status` 1,984 B；`worker_events` 543 B；busy Worker 的 wait/status/events 为 345/396/549 B，304 条 progress 全部省略。
- 测试稳定性：开发过程中一次全量运行出现过 1 次 `idempotency` 测试失败，原因是 Windows Daemon lock 的 PID identity 校验在高压下拒绝了重启；该文件单独复跑 9/9 通过，最终精确树全量 405/403/2 通过，未发现与 MCP 改动相关的回归。

## 7. Phase 7 独立审计

独立审查覆盖 20 个工具的 Production/Development 路径、参数绕过、错误投影、旧 Daemon 兼容、分页与测试有效性。结论：**无阻断项**。审查后补强：

- `worker_resume.sessionRestored` 在旧 Daemon 无 session 投影时省略，不写 false。
- `worker_wait until=event` 事件批次限制为 10 条/4 KiB，并新增单元回归。
- `worker_list` cursor 要求规范 ISO 时间戳，非规范值返回 `BAD_REQUEST`。
- 删除不可达的 Production 原始事件投影分支，事件只能经白名单摘要返回。
- Development `worker_events` 描述与实现对齐：始终返回存储流，`includeProgress` 仅为跨模式兼容参数。
- `types:[]` 回归改用延迟 progress 场景，确保修复前会失败。
- `supervisor_info.runtimes[].available` 明确表示 adapter 已注册，不是运行时真实可用性探测。
- Development `session.ref.sessionLocator` 会返回原生 session 文件路径（诊断用途）；Production 永不返回。

## 8. 已知限制与未验证

- `worker_wait` 历史分页有一个已知 P2：`until=event` 配合类型过滤时只检查游标后前 500 条，目标在后页且任务仍运行时可能误超时；当前可用 `worker_events` 推进游标。见 `docs/backlog.md`。
- Development 的 ACK 逐 id 诊断、`wake_target` 变更前目标/校验明细、wait 扫描耗时、events 256 KiB 硬预算未实现，原因是当前 IPC 不提供对应数据；0.9.1 不在返回层推断或伪造。
- Production 的 2 KiB/4 KiB 是上下文预算，不是安全边界；`includeInput=true`、`until=event`、`state=all` 等显式读取可以超过默认体积。
- Production `cwd` 只是默认工作目录，不是文件系统沙箱；Worker 与 daemon 使用同一 OS 用户。
- 未验证：Codex Desktop 模型回合、Persistent Worker 多轮 MCP 调用、Pi/DSH 的真实 MCP 验收、权限审批交互、生产环境升级。

## 9. 升级与兼容

- 升级后重启 daemon 和 MCP server（或宿主会话），使版本检查和新契约生效。
- 状态目录、事件文件、Worker 记录无需迁移；旧记录继续可读。
- `worker_list` 从数组改为 `{workers,nextCursor,hasMore}`，依赖旧数组格式的客户端需要适配；Production 条目为摘要。
- `worker_status` 不再返回完整结果/事件；完整结果使用 `worker_wait`，事件使用 `worker_events`。
- Production 需要 daemon ≥0.4.0；`worker_list` cursor 需要 daemon ≥0.9.1；metrics 需要 daemon ≥0.5.0。
- 发布动作（版本 tag、远程推送、生产部署）未执行，按用户后续指示处理。
