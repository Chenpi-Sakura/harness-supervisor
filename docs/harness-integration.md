# 新增 Harness 接入指南

新增 Harness 的完成标准是：原生执行与权限可靠、各入口能够发现和使用、WebUI 显示完整、使用文档准确。Adapter 能启动不代表接入已经完成。本文是维护指南，具体接口与支持能力以当前代码和真实验证为准。

## 1. 协议、权限与运行基础设施

优先使用 Harness 的原生协议；支持 ACP 时，先核对实际安装版本的协议与能力协商，不根据产品名称推断支持情况。不支持 ACP 的 Harness 仍可通过原生协议实现 Adapter，不强行包装成 ACP。

| 工作 | 主要检查位置 | 验收要求 |
| --- | --- | --- |
| Adapter 契约 | `src/types.ts`、`src/adapters/` | 实现真实支持的生命周期操作，明确能力与限制；不在 Supervisor 中复制厂商协议 |
| ACP 通信 | `src/adapters/acp/client.ts`；参考 `src/adapters/native-acp/` | 初始化、会话创建、增量事件、请求关联、错误、断连与进程清理均有处理 |
| 安装与启动 | 对应 Adapter 的 launch 实现、`src/daemon.ts` | 注册 runtime；支持 Windows 路径和进程启动；缺少依赖时给出可执行的安装提示；不在任务启动时偷偷下载 |
| 权限与交互 | Adapter Session、统一 input/answer 契约 | 只接受原生提供的权限选项；校验会话和请求归属；处理重复回答、超时、取消和连接关闭。权限请求支持不等于任意问题输入支持 |
| 模型与配置 | Adapter 的能力协商及配置设置 | 验证模型、推理强度是否被提供和确认；区分 Harness、请求模型和实际上报模型；不能把默认配置猜成实际模型 |
| 生命周期 | Adapter、`src/supervisor.ts` | 区分已接受、正在工作、等待输入、完成、取消和异常；终态基于原生证据；持久续接和进程重启恢复分别验证 |
| CLI / MCP | `src/cli.ts`、`src/mcp.ts`、`src/mcp-presentation.ts` | 帮助、参数描述、能力发现、错误和返回语义一致；生产模式维持响应预算与会话隔离 |
| 事件与用量 | Adapter 的事件映射及现有事件展示/合并实现 | 连续文本按协议语义合并；保留游标和原始记录；不跨工具调用或不同消息乱拼；缺少用量不能伪造真实值 |
| 安装包 | `scripts/pack-core.mjs`、插件打包和发布校验 | 明确依赖由谁安装；发布物具备必要资源；源码可运行不等于干净环境安装可运行 |

复用 `native-acp` 前先判断其标准权限、模型设置、恢复与消息语义是否适合新 Harness。厂商专属扩展放在对应 Adapter；不可为了复用宣称不存在的能力。独立安装的 ACP 桥接器与 HS 版本分开管理，更新后需要重新验证，不把“使用最新版”当成兼容保证。

### 验证顺序

1. 协议模拟测试：正常完成、错误响应、断连、无效模型、权限回答、取消、恢复失败及清理。
2. HS 集成测试：通过 daemon / IPC 启动、等待、读取结果、回答权限、取消及重复操作；确认 CLI / MCP 的行为一致。
3. 真实 Harness 验证：在隔离工作目录和状态目录中运行合成任务，用文件读取等独立证据核对结果；持久会话测试同进程 continue，再测试退出后的 resume。确实不支持的操作明确拒绝。
4. 核对异常与资源：残留子进程、启动失败、取消期间待处理请求、凭据泄漏、日志体积和历史状态兼容。

参考现有 `test/unit/native-acp.test.ts`、`test/integration/native-acp.test.ts` 与 `test/fixtures/fake-native-acp.ts`。测试脚本以 `package.json` 为准；不要把旧脚本名称中出现某个 Harness 当成已经覆盖新 Adapter 的证据。报告区分真实、模拟和未验证能力，并记录真实测试所用 Harness、ACP 桥接器及模型版本。

## 2. WebUI 与展示基础设施

| 检查项 | 主要位置 | 完成标准 |
| --- | --- | --- |
| 名称和图标 | `web/src/harness-icons.tsx`、`harness-icons.css`、`assets/harness/` | 显示正式名称；使用本地品牌图标，保留来源与许可；已支持厂商不落到通用终端图标 |
| 品牌色 | `web/src/worker-relations.css` 及实际侧栏样式 | 按可核实的品牌来源配置；深浅主题均可辨认；品牌底色不覆盖正在工作、异常等状态边框，Master 保留专属边框 |
| 侧栏与筛选 | `WorkerNavigation.tsx`、`WorkerFilters.tsx` | 名称、搜索、厂商筛选、工作目录→会话→Worker 分组都正确 |
| 关系图 | `WorkerRelations.tsx` | 图标、底色、模型、状态、持久/一次性边框、工作动效与详情入口完整；项目和会话切换正确 |
| 详情与数据 | `web/src/main.tsx`、`src/web-ui.ts` | Harness 与模型分开表达；结果 Markdown、事件、审批、取消、用量及未知值语义正确；只传必要字段，不暴露凭据 |
| 事件呈现 | `web/src/event-presentation.ts` 及现有输出合并实现 | 文本片段显示可读，工具、权限与生命周期边界仍清楚；Master 的精简返回与网页展示分别验证 |

必须用包含新 Harness 的预览/测试数据检查侧栏、画布、筛选和详情，并检查真实数据流。至少覆盖深浅主题、选中与悬浮、正在工作/等待输入/完成/取消/异常，以及详情侧栏展开和全屏。未知型号保留未知，界面的 0 占位不能冒充已上报用量。

## 3. 文档更新范围

- 更新主 `README.md`：安装前提、当前接入、能力与限制、使用示例和验证说明。只调整与本次功能有关的部分；不为了新 Harness 重写整份 README。
- 更新受到影响的现行功能说明，例如 `packages/dsh-plugin/README.md` 中的支持范围、安装方式和设置说明，以及本指南涉及的接口变化。
- 不要求维护一份重复真相的中文/其他语言 README；若存在独立翻译，不把同步翻译作为接入的默认门槛。
- **不回改历史文档**：版本技术报告、历史验收证据、日期化调查记录与 `docs/archive/` 描述当时事实，不能改成今天已经支持。若今天行为改变，在现行功能文档说明。
- `AGENTS.md` 只放长期约束和指南入口，不维护不断变动的厂商清单、验证版本或任务流水账。文档与实现不符时先核对代码与运行证据，不以文档替代验证。

## 4. 交付检查

- 协议、权限、生命周期、错误提示和依赖安装已覆盖；不支持能力有明确边界。
- CLI / MCP 能发现并使用新 runtime，生产返回和通知仍符合预算与归属限制。
- WebUI 正式名称、图标、许可、品牌色、模型、状态、筛选、详情与真实数据流已核对。
- 定向测试、类型检查和构建通过；共享核心变动按项目规范做全量验收，说明环境性失败和未验证项。
- 现行功能文档已同步，历史报告不改写。
- 按 `AGENTS.md` 联动核心和插件版本、构建与发布；核实 npm 公开结果。发布不等于升级生产实例。
